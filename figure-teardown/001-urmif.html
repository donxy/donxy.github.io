02

整体观感

Overall Impression

这篇论文的绘图辨识度来自三个签名：

1

粉彩模块色＋3D 板片

所有网络模块都画成带垂直渐变的梯形板片堆叠，颜色按模块家族编码（绿 = IR 支路、蓝 = VIS 支路、玫红 = 主平面解码器、紫 = 融合支路），饱和度压在中低区间，整图没有一块刺眼的纯色。

2

圆体粗标题

分图标题与图中文字标签使用圆角粗无衬线体（视觉上接近 Comic Sans / Baloo 一类圆体，inferred），与 TPAMI 常见的 Helvetica / 宋体式标注形成鲜明反差——亲和力强，是这组图最容易被认出的特征（也是它唯一的争议点，见 07 末）。

3

「照片进、照片出」的伪 3D 空间

输入输出照片被做透视倾斜处理，与特征张量板片处在同一套伪三维空间里，整张图像一条在三维流水线上流动的装配线。

数据集图与框架图共享同一语言：同样的圆角、同样的粉彩、同样的渐变药丸与虚线框——一篇论文的两类图（方法图＋数据图）保持同一视觉身份，这是很多论文做不到的。

03

逐图拆解

Figure by Figure

图 A框架总览图 · 面板 (a) UMFR（约占宽 38%）

  • 构图是严格的双行对称：上行 IR（图像→绿色编码器堆叠 ℰIR→右侧解码器群），下行 VIS（图像→蓝色编码器堆叠 ℰVIS→解码器群），中行是共享的主平面解码器 𝒟DP。三台解码器 𝒟VIS / 𝒟DP / 𝒟IR 在右侧纵向排开，输出端各贴一组小照片（重构图 / 平移图 / 掩膜）。
  • 数据流是粗黑实线箭头；两类损失回路用彩色虚线箭头反向走：红色虚线 = Reconstruction Loss，蓝色虚线 = Translation Loss（measured：红 #D32525、蓝 #382BCC，各自由数千个饱和像素统计得到）。虚线从解码器绕回编码器与输入端，在图面下方汇成图例行（红虚线箭头＋「Reconstruction Loss」、蓝虚线箭头＋「Translation Loss」）。
  • 编码器画成 4–5 片梯形板，高度沿数据流方向递减（汇聚），解码器镜像递增（发散）——板片高度的收分本身就在讲「分辨率 / 通道的变化」，不需要文字说明。
  • 数学符号 ℰ、𝒟 与变量 IIR、IVIST 等用 LaTeX 斜体衬线，与圆体标签形成「公式归公式、标签归标签」的字体分工。

图 A框架总览图 · 面板 (b) 双向耦合配准-融合（约占宽 62%）

  • 与 (a) 之间以一条竖直虚线分隔，虚线中点嵌一枚灰色右向箭头尖——既是分界也是阅读方向提示（inferred，但位置精确居中，很难是无意）。
  • 内部仍是 IR 上、VIS 下的双行结构：编码器堆叠→线框热力图板（紫色线框盒＋jet 热力面，板面上有细的紫色双向弧线箭头，表示跨模态相关计算）→圆圈点积符号 ⊙→紫色线框的形变后特征板→汇入全图英雄元素 Deformation Aggregator（见 05）。
  • Aggregator 下方分出两条 Warp 路径（极浅蓝药丸按钮＋绿黄渐变倾斜平面表示全局 / 局地形变场），Warp 后的特征上行进入右上方的融合区：上方一路经蓝色板片堆叠（配准支路），下方一路经绿色金字塔堆叠（多尺度特征），在玫粉色药丸 Fusion 处汇合，再经紫色融合解码器输出 IFus 照片。
  • 两个带圈数字 ①② 精确压在 Aggregator 的两条耦合箭头上——「双向耦合」这一核心主张被标注在它发生的确切位置，而不是写在图注里。
  • 面板底部有一条阶段括号轴：左段「Modality-Homogeneous Image Alignment」，右段「Modality-Heterogeneous Image Fusion」，用一条横线加端点刻度把整段流程切成两个阶段——读者扫一眼底部就知道流程的相位划分。

图 BRIVIR 数据集图

  • 版式是非对称网格：(a) 共现图占左侧约 40% 通高；右侧 2×2 四格 (b)(c)(d)(e)。五格全部用同款深灰虚线圆角框圈起（measured：虚线灰 #4E4D50），子标题为衬线体（Times 类）居中置于框下。

色彩拆解

Colour System

框架图主色板（measured，采样自原图 PNG；板片为垂直渐变，取面中调代表值）。点击任意色卡即可复制 HEX。

融合紫 · 紫罗兰家族家族色融合解码器、线框板描边、Aggregator 右半——一切「融合 / 形变后」元素
数据流箭头 · 近黑与正文黑同级全部实线箭头、文字

配色规则提炼（可迁移）

  • 颜色只编码「模块家族」，不编码重要性；重要性靠尺寸与位置（英雄框）表达。于是颜色系统可以全程低饱和，图面不吵。
  • 两个面板的底色 wash 是两支路色的「极淡版」：(a) 绿、(b) 蓝，饱和度低到近白，只够让读者潜意识分组，不够抢内容。
  • jet 热力色被关在笼子里：只出现在特征板表面这一种语境，全图其他地方禁用高饱和彩虹色——热力图的「闹」因此变成信息本身而不是噪声。
  • 损失用全图仅有的两个高饱和纯色（红 / 蓝），且只给虚线——高饱和是稀缺资源，只花在需要一眼定位的语义上。

数据集图色板

底色纯白；虚线框炭灰 #4E4D50（measured）；条件药丸为纵向渐变，天蓝→薰衣草（中段实测 #BAB4DC）→粉紫；共现图群落色为粉彩蓝 / 紫 / 青 / 粉四族（视觉估计，未逐点采样）；照片本身不做色调统一，保留真实拍摄的杂色——与框架图的「全受控」相反，这里用不受控的真实照片衬托受控的标注层。

共现图群落色 · 粉彩四族视觉估计蓝 / 紫 / 青 / 粉四族，未逐点采样
05

图形拆解

Visual Components

组件清单（编号与本系列组件库同步）：

C-001

梯形板片堆叠

4–5 片等距板片，高度沿流向收分，每片垂直渐变（上浅下深）＋细深色描边，顶面留一条窄高光面作「厚度」。编码器与解码器靠收分方向区分，不靠文字。

C-002

线框热力图板

长方体线框只留紫色棱线，正面贴 jet 热力图，板面叠加细弧线双向箭头。用于「待对齐 / 已对齐的特征」，与实心板片形成「数据态 vs 模块态」的质感区分。

C-003

立方体网格聚合器 英雄组件

大圆角矩形，描边为蓝→紫渐变（见 07），填充薰衣草紫；内部 4×3 小立方体网格，左半蓝灰、右半粉紫，两半各自带弧线双向箭头。模块名置于框内下方，圆体粗字两行居中。

C-004

倾斜照片平面

输入 / 输出照片做单点透视倾斜（左缘高、右缘矮的等距感），与板片共享伪 3D 空间；输出 IFus 的倾斜角度最大，像被「递」出画面。

C-005

渐变场平面

绿→黄渐变的倾斜薄片表示形变场（全局 / 局地各一），是全图唯一用连续渐变面表示「场」的组件。

C-006

药丸按钮 / 标签

圆角满格的 pill，两种用法——框架图里作模块（Warp、Fusion，浅填充＋同色系描边＋深色字）；数据集图里作跨缝标签（渐变填充＋衬线黑字）。

C-007

虚线圆角分框

数据集图五格统一的深灰虚线框；框架图中同一虚线语言被复用为面板分隔线。

C-008

阶段括号轴

横线＋端点短竖刻度＋段名，两段在 Aggregator 下方交界，与上方结构对位。

C-009

词云共现网络

字号 = 频率，颜色 = 群落，细弧线 = 共现，见 03。

箭头系统

实线箭头——粗（在 3010px 宽原图上约 6–8px，目测）、等腰三角箭头头、走直角折线（先水平后垂直的肘形路由），全图统一，只走数据流。

虚线箭头——只属于损失：红色 = Reconstruction Loss，蓝色 = Translation Loss。

弧线小箭头——只属于「板内交互」（跨模态相关、聚合器内部耦合）。

三种箭头三类语义，零混用。

06

布局拆解

Layout & Composition
  • 超宽单行叙事：3.37:1 的画布把「表示学习→配准→融合」排成一条左→右的装配线，两个面板的宽度比（约 38:62）直接对应两部分的方法体量——布局先于文字交代了论文的重心在 (b)。
  • 双行对称骨架：两面板内部都是 IR 上行、VIS 下行，读者的眼睛在 (a) 学会的阅读规则在 (b) 直接复用，学习成本只付一次。
  • 三级信息层级：第一级 = 英雄框与两张端点照片（最大、最饱和）；第二级 = 板片堆叠与热力图板（中尺寸、家族色）；第三级 = 虚线损失、圈码、图例（细线、小字）。层级靠尺寸与线宽拉开，颜色始终克制。
  • 留白：面板内元素间距大致等于一个板片厚度，wash 底色让「空」看起来是「底」而不是「缺」；图例条与主图之间留一条完整的空白带，图例因此不被误读为流程的一部分。
  • 数据集图用 (a) 的大面积纹理化词云平衡右侧 24 张小照片的视觉重量，左右重量相当，网格不塌。
07

精致感来源

Where the Polish Lives

最值得学的、第一眼看不见的细节：

  1. 英雄框的渐变描边

    Deformation Aggregator 的边框从左侧蓝过渡到右侧紫——正是 VIS 蓝与融合紫的混合。这条边在无人讲解时就把「两路信息在此汇合」讲完了，是全图最贵的一笔。

  2. 聚合器内部的双色立方体

    网格左半蓝灰、右半粉紫，等于把「聚合两个模态的形变」画成了字面图景；两半各自的弧线箭头方向还不同（左半竖向、右半横向，目测），暗示两种形变模式。

  1. 蓝色调的投影

    板片堆叠的投影 / 辉光带蓝色调（𝒟VIS 后方可见明显的浅蓝晕），阴影不是灰的——整图的光线被统一染成冷色，画面因此「干净」。

  2. 损失图例放在面板内部底部

    而不是全文图注：读者在 (a) 内就能闭环理解红蓝虚线，视线不用离开图面。

  1. 药丸压缝

    数据集图的标签药丸精确压在可见光 / IR 两图的接缝上，一半在上、一半在下——标签在几何上就属于「这一对」，不属于任何单张。

  2. 保留 FLIR 水印与温度标尺

    IR 照片右下角的相机界面元素没有被裁掉，这是「真实采集」最廉价也最有效的证据，比任何文字声明都硬。

  3. 圈码位置

    ①②不在标题、不在图注，而在箭头线上——步骤编号与数据流共用一条路径，读图顺序被箭头本身强制。

必须指出的瑕疵（拆解不是吹捧）

圆体标题在 TPAMI 的语境里偏活泼，正式感弱于主流期刊图；(b) 中段线框板＋聚合器＋双 Warp 路径挤在一竖列，密度明显高于全图其他区域，是全图唯一需要「找路」的地方；数据集图 (a) 子标题在原图里把 Co-occurrence 拼成了「Co-occurence」，(e) 的「Smooth inspect」也是中式英语——图进正文前的文字校对没跟上绘图水准，这条教训同样可迁移。

09

设计总结

Takeaways

可迁移的 5 个技巧：

  1. 颜色只编码家族，重要性交给尺寸

    全图低饱和不等于平淡——把唯一的放大＋渐变描边给核心创新模块，层级立刻成立，且颜色系统可无限复用。

  2. 线型即语法

    实线黑箭头 = 数据流、彩色虚线 = 损失、细弧线 = 板内交互。语义分工写在线型里，读者不需要查图例就懂箭头的意思。

  3. 近白 wash 分面板

    两个子系统各铺一层各自支路色的极淡版底色，分组在潜意识层完成，不占任何标注资源。

  4. 英雄组件要「画出主张」

    聚合器的双色立方体＋渐变边框把论文的核心机制（双向耦合两个模态）做成了字面图景——核心模块的内部结构值得单独设计，而不是套用统一模板。

  5. 样本绑定靠几何

    数据集图的药丸压缝、照片对的上下对位、保留相机水印——用版式与真实痕迹证明「成对」与「真实」，比加文字说明有效。
